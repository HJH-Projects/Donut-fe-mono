# PR 템플릿(상세)

아래 형식은 에이전트 브랜치 → 도메인 브랜치 PR에 사용합니다.
구현 방식 섹션에서는 **데이터가 다음 단계에서 어떻게 사용되는지**를 반드시 명시합니다.

```
제목: [type/domain] <핵심 목적 한 줄>

범위
- 담당 도메인: <auth|home|closet|look|my>
- 주요 화면/기능: <구체적으로>
- 영향 경로(핵심): <파일/폴더 3~7개>

구현 위치 (파일별 요약)
- <파일A> : <무엇을 구현했는지 + 주요 함수/컴포넌트>
- <파일B> : <무엇을 구현했는지 + 주요 함수/컴포넌트>
- ...

구현 방식 (흐름 + 데이터 사용)
- 입력/트리거: <사용자 액션 또는 라우팅 진입>
- 처리 단계:
  1) <첫 단계 처리> → <생성/획득된 데이터>
  2) <다음 단계 처리> → <앞 단계 데이터 사용 방식>
  3) <최종 단계 처리> → <화면/상태 반영>
- 데이터 흐름:
  - SSR: <어떤 함수에서 어떤 데이터 생성> → <다음 단계 사용>
  - CSR: <어떤 함수에서 어떤 데이터 생성> → <다음 단계 사용>
  - Mock: <어디서 어떤 형태로 반환> → <어떤 화면에서 소비>

설계/의도 (구체 이유)
- <왜 이 위치(서버/클라이언트)에서 처리했는지>
- <왜 이 방식(예: postMessage, middleware, SSR 우선)을 택했는지>
- <대안 대비 이점>

검증
- 확인한 동작: <구체 시나리오>
- 미확인/리스크: <추가 테스트 필요>
```
