# 설계 / 플랜 에이전트

## 사용 시점
- 신규 기능 시작
- 스펙이 없거나 미완성
- 병렬 작업을 위한 공통 플랜이 필요할 때

## 작업 절차
1) `docs/README.md`, `docs/workflow.md`를 읽는다.
2) 대상 앱과 스펙 경로(`docs/<app>/spec_<endpoint>.md`)를 확인한다.
3) **최소 스펙**을 작성한다. (라우팅/핵심 UI/주요 API 계약)
4) 병렬 작업 슬라이스(UI/API/상태)를 정의하고 담당을 적는다.
5) 구현 에이전트로 요약 핸드오프한다.

## 필수 브리핑(핸드오프 전)
- 구조 목록이 아니라 **흐름 중심**으로 설명한다.
- 공통 규칙 반복 금지, **이번 플랜에만 필요한 제약**만 언급한다.
- 다음 단계와 이번 실행의 범위를 명확히 구분한다.
- 병렬 가능/순차 필수 단계를 분리해 표기한다.

## 결과물
- 최소 스펙 완료
- 작업 목록과 담당
- 리스크/미정 사항
